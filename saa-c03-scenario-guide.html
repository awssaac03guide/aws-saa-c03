How to use this guide

  1. Open a domain tab. Read the scenario, pick your option(s), then press Check answer.
  2. Press ▶ Play explanation for the walkthrough at normal 1x speed. The button changes to Pause, then Resume; a separate Stop button resets playback. Resume restarts the highlighted sentence.
  3. Timing is approximate (~45 seconds) and varies by your browser voice. Read the review technique and pro tip, then classify any miss (A-E below).
  4. Use Multi-response only to drill combination questions; use Reveal all for fast revision.

Universal method: R-C-A-E

  1. Requirement — what outcome is being bought (HA, DR, latency, cost, compliance)?
  2. Constraint — the qualifier that decides it: LEAST overhead, no code change, RPO/RTO, private only, cost.
  3. Architecture — name the pattern before reading the options.
  4. Eliminate — strike options that break any one constraint; compare the last two only on the deciding constraint.

Qualifier decoder

LEAST operational overheadManaged or serverless feature over self-built (EC2 scripts, cron, custom code)
LEAST development effort / no code changesConfiguration-level fixes: Multi-AZ, RDS Proxy, CloudFront, endpoints, lifecycle rules
MOST cost-effectiveCheapest option that still meets every stated requirement, not the cheapest overall
Near real time / millisecondsRules out batch, polling, Athena-on-S3 and daily jobs
Must not traverse the internetVPC endpoints, PrivateLink, Direct Connect; not NAT gateways
RPO / RTO numbersRPO limits data loss; RTO limits recovery time. Check replication lag and recovery steps separately: fast replication alone does not guarantee fast failover.

Multi-response technique

  1. List each requirement separately; each correct option usually satisfies one of them.
  2. Judge every option as true/false on its own, then pick exactly two. Each multi-response item here is choose two from five options.
  3. Two options that do the same job are rarely both correct; two halves of one mechanism (create + attach, enable + configure) often are.
  4. Drop any option that adds a new single point of failure or violates the overhead/cost qualifier.

Classify every miss

A. Service knowledgeYou did not know what the service does.
B. RequirementYou misread what the scenario asked for.
C. Trap pairYou knew both services but swapped their use cases.
D. ConstraintYou ignored LEAST overhead, no code changes, downtime limits.
E. Exam readingYou knew it but picked a plausible distractor.

Q59

Certificate-only access for field devices

Single answer

A utility company has 6,000 field devices that send readings to an HTTPS API behind an internet-facing Application Load Balancer, which routes by path to Amazon ECS services and is protected by an AWS WAF web ACL. Each device holds an X.509 client certificate issued by the company private certificate authority, and the security team publishes a certificate revocation list every day. Security now requires that any connection without a valid, unrevoked certificate from that authority is rejected before a request reaches a container. The application team will not add certificate-validation code, but it can read a request header to map the certificate subject to a device ID. The ALB, its path routing, and the web ACL must stay.

Which solution meets these requirements?

Correct: DTrap pair: Picking mutual TLS passthrough because it also uses client certificates, even though it leaves all verification to the application code.
~52s at 1x · 129 words

Option D is correct. In mutual TLS verify mode the Application Load Balancer authenticates each client certificate against the CA bundle in its trust store and checks the revocation list during the TLS handshake, so untrusted or revoked devices are rejected before any request reaches a container. The load balancer then passes the certificate subject to targets in an X-Amzn-Mtls header for authorization, and path routing and the web ACL stay in place. Option A is wrong because passthrough mode does not verify certificates, so the containers would need validation code. Option B is wrong because a Network Load Balancer does not authenticate client certificates and drops path routing and the web ACL. Option C is wrong because Cognito authentication is an interactive user sign-in flow, not certificate authentication.

Question review technique

Underline "rejected before a request reaches a container", "will not add certificate-validation code", and "the ALB, its path routing, and the web ACL must stay". Client certificates plus no code means the load balancer must do the verification itself, which separates verify mode from passthrough mode and rules out replacing the load balancer.

X.509 client certificate from a private authoritycertificate revocation listno certificate-validation codeALB and web ACL must stay

Pro tip

ALB mutual TLS has two modes: verify, where the load balancer authenticates certificates against a trust store with optional revocation checks, and passthrough, where it only forwards the certificate chain. Choose verify mode when the application must not handle certificate validation.

Q85

Gray failure in one Availability Zone

Single answer

A retail API runs on EC2 instances in an Auto Scaling group across three Availability Zones behind an Application Load Balancer with cross-zone load balancing enabled. During a recent incident, instances in one zone kept passing their lightweight health checks, but requests served there had 4-second latency and intermittent 5xx errors because of a zone-level network impairment. Engineers spent 50 minutes editing subnets and capacity to drain the zone. The company wants an operator to move traffic away from a single impaired zone within minutes, with no DNS record changes, no redeployment, and no application code changes, and the change must end on its own after a set time. The remaining two zones have enough headroom.

Which solution will meet these requirements with the LEAST operational effort?

Correct: DTrap pair: Reaching for deeper health checks or Region failover for a gray failure, when the requirement is a fast, temporary move away from one Availability Zone.
~52s at 1x · 130 words

Option D is correct. A zonal shift in Application Recovery Controller marks one Availability Zone unhealthy for a supported load balancer, so traffic moves to the other zones in minutes without DNS edits, redeployment, or code changes. Every zonal shift must have an expiration, up to three days, so it ends on its own unless an operator extends or cancels it. Option A is wrong because a second Region adds a standby stack and DNS failover for a problem confined to one zone. Option B is wrong because editing subnets is the slow manual process that took 50 minutes, and someone must remember to undo it. Option C is wrong because deep health checks require new endpoint code and can fail every zone at once when a shared dependency fails.

Question review technique

Underline "single impaired zone", "within minutes", "no DNS record changes, no redeployment, and no application code changes", and "end on its own after a set time". A zone-scoped, operator-started, time-limited traffic move is exactly what zonal shift provides, so eliminate Region failover, manual subnet edits, and new health check code.

passing health checks but degraded zonemove traffic away from one zone in minutesno DNS, redeployment, or code changesends after a set time

Pro tip

Zonal shift moves traffic away from one Availability Zone for ALBs, NLBs, EC2 Auto Scaling groups, and EKS, and always expires. Zonal autoshift lets AWS start the shift when it detects a zone impairment. A load balancer that is failing open will not shift traffic.

Q124

Multi-hop fraud links in a relational database

Choose two

A payments company stores accounts, devices, cards, and IP addresses in Amazon RDS for PostgreSQL. Fraud analysts and a real-time scoring service run recursive queries that find accounts linked through shared devices or cards up to four hops away. Each query now takes 6 to 12 seconds, and the scoring service needs answers in under 100 ms. Read volume is about 15,000 traversals per second and is growing, while writes stay near 500 per second. The team is willing to rewrite only the traversal queries in a graph query language, wants a fully managed service, and needs reads to keep working if one Availability Zone fails.

Which combination of steps should a solutions architect recommend? (Choose two.)

Correct: C, ETrap pair: Adding relational read replicas or a bigger instance, which raises throughput or headroom but leaves each recursive multi-hop query slow.
~51s at 1x · 128 words

Option C and Option E are correct. Neptune is a managed graph database that stores relationships directly, so a four-hop link search becomes a short openCypher traversal instead of repeated recursive joins, which brings latency into the millisecond range. Neptune read replicas in other Availability Zones share the cluster storage, the reader endpoint spreads traversal load across them, and a replica can take over if the primary zone fails. Option A is wrong because replicas add throughput but each recursive query still takes seconds. Option B is wrong because issuing one query per hop multiplies round trips and fan-out, so four hops cannot meet 100 ms. Option D is wrong because a larger instance and indexes cannot turn multi-second recursive joins into sub-100 ms answers at this volume.

Question review technique

Split the problem into per-query latency and read scale. Multi-hop relationship queries that are slow in SQL point to a graph database, which fixes latency. Then look for the step that scales reads and survives a zone failure for that same database, and eliminate options that only scale the relational engine.

linked up to four hops awayunder 100 ms15,000 traversals per secondrewrite only the traversal queries

Pro tip

When the question stresses relationships several hops deep, think Amazon Neptune with Gremlin, openCypher, or SPARQL. Scale its reads with up to 15 read replicas behind the reader endpoint, which also provide failover targets.

Q188

Transit gateway bill from one VPC pair

Single answer

A company connects 32 VPCs and its data center through one transit gateway in us-east-1, and every VPC route table sends 10.0.0.0/8 to the transit gateway. A cost review shows about $8,000 per month in transit gateway data processing, almost all from one pair: an analytics VPC (10.20.0.0/16) whose cluster of 300 instances reads about 400 TB per month from many hosts and ports in a data ingestion VPC (10.30.0.0/16). Both VPCs are in the same account, and most of this traffic stays within the same Availability Zones. Neither workload can be redeployed or changed, all other traffic must keep using the transit gateway, and throughput must not be capped.

Which solution will reduce this cost MOST effectively?

Correct: CTrap pair: Assuming that a dedicated transit gateway or PrivateLink cuts cost, when both still bill for every gigabyte processed.
~50s at 1x · 126 words

Option C is correct. A VPC peering connection has no hourly or data processing charge, and data transfer over it that stays within an Availability Zone is free, so most of the 400 TB costs nothing to move. The /16 peering routes are more specific than the 10.0.0.0/8 route, so only this pair leaves the transit gateway path, and peering has no bandwidth bottleneck. Option A is wrong because PrivateLink also charges per gigabyte processed and exposes services through a load balancer, which does not fit hundreds of hosts and ports. Option B is wrong because a second transit gateway still charges data processing for every gigabyte. Option D is wrong because launching the cluster in shared subnets means redeploying a workload that cannot be moved.

Question review technique

Find where the per-gigabyte charge comes from, then look for a path that removes it without breaking a constraint. A heavy flow between two VPCs is the classic case for peering beside a transit gateway, and longest-prefix routing lets you peel off one pair while every other route stays the same.

transit gateway data processing400 TB per month between two VPCssame Availability Zonesother traffic must keep using the transit gateway

Pro tip

Transit gateways bill per attachment-hour and per gigabyte processed. For one high-volume VPC pair, add VPC peering with more specific routes: there is no hourly charge, and same-AZ traffic over peering is free.
